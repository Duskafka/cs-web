# 가상 DOM

실제 DOM 조작은 [[브라우저 렌더링 파이프라인]]의 Layout 을 유발해 비싸다. 가상 DOM 은 UI 를 평범한 자바스크립트 객체 트리로 표현하고, 변경 전후를 비교(diffing)해 **바뀐 부분만** 실제 DOM 에 적용한다.

## 휴리스틱

일반적인 트리 비교는 `O(n^3)` 이라 실용적이지 않다. React 는 두 가지 가정으로 `O(n)` 에 끝낸다.

1. 타입이 다른 두 요소는 완전히 다른 트리를 만든다.
2. 개발자가 `key` 로 형제 노드의 동일성을 알려준다.

`key` 에 배열 인덱스를 쓰면 순서가 바뀔 때 잘못된 노드가 재사용되어 상태가 엉킨다.

## 오해

가상 DOM 이 직접 DOM 조작보다 항상 빠른 것은 아니다. 진짜 이득은 **선언적으로 쓰면서도 최악의 성능을 피할 수 있다**는 점이다.

## 연결

- 트리 비교는 결국 [[그래프 탐색]]의 응용이다.
- diff 결과를 적용하는 타이밍은 [[이벤트 루프]]의 태스크 큐에 달려 있다.
