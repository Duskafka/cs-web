# 브라우저 캐시

가장 빠른 요청은 **보내지 않는 요청**이다.

## 두 단계

- **강한 캐시**: `Cache-Control: max-age=31536000` 이면 만료 전까지 네트워크에 나가지 않는다.
- **재검증**: 만료 후 `If-None-Match: <ETag>` 를 보내고, 서버가 `304 Not Modified` 로 답하면 본문 없이 캐시를 재사용한다. 상태 코드는 [[HTTP]]에서 정리했다.

## 캐시 무효화 문제

정적 자산은 오래 캐시하고 싶지만 배포하면 새 파일을 받아야 한다. 해법은 파일명에 콘텐츠 해시를 넣는 것(`app.3f2a9b.js`)이다. 내용이 바뀌면 URL 이 바뀌므로 캐시가 자연스럽게 갈린다. 해시 계산은 [[해시 테이블]]에서 쓰는 것과 같은 함수군이다.

## 연결

- 서버 쪽 대응물이 [[캐싱 전략]]이다.
- [[DNS]] 캐시와 CDN 캐시까지 합치면 요청 하나가 통과하는 캐시 계층은 네 겹이 넘는다.
- 캐시된 리소스가 언제 파싱되는지는 [[브라우저 렌더링 파이프라인]]에 달려 있다.
