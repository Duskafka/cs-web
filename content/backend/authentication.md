# 인증과 인가

**인증(authentication)** 은 "누구인가", **인가(authorization)** 는 "무엇을 해도 되는가"다. 로그인은 됐지만 남의 주문을 조회할 수 있다면 인증은 통과했고 인가가 뚫린 것이다.

## 세션과 토큰

| | 세션 | JWT |
| --- | --- | --- |
| 상태 | 서버가 보관 | 토큰 자체에 담김 |
| 확장 | 저장소를 공유해야 함 | 서버가 기억할 게 없음 |
| 무효화 | 지우면 끝 | 만료 전까지 유효 |

JWT 의 장점인 무상태는 그대로 단점이 된다. 탈취된 토큰을 즉시 끊을 수 없어서, 수명이 짧은 액세스 토큰과 서버가 기억하는 리프레시 토큰으로 나누는 구성이 흔하다. 결국 상태가 서버로 돌아온다.

## 비밀번호는 암호화하지 않는다

복호화할 일이 없으므로 **단방향 해시**를 쓴다. 다만 빠른 해시는 공격자에게도 빠르므로 bcrypt 나 Argon2 처럼 의도적으로 느리고 사용자마다 다른 솔트를 붙이는 함수를 쓴다.

## 연결

- 토큰이든 세션 ID 든 평문으로 흐르면 그대로 탈취되므로 [[HTTPS와 TLS]]가 전제다.
- 서버가 세션을 보관한다면 그 저장소는 [[캐싱 전략]]에서 다루는 것과 같은 인메모리 저장소다.
- 세션 ID 로 사용자를 찾는 조회는 [[해시 테이블]]의 전형적인 사용처다.
- 인가 실패를 어떤 상태 코드로 돌려줄지는 [[REST API 설계]]의 문제다.
