컨텍스트 스위칭은 CPU가 한 프로세스(또는 스레드)에서 다른 프로세스로 실행 제어를 넘길 때, 현재 상태를 저장하고 다음 상태를 복원하는 과정을 말한다.

OS의 스케줄러가 여러 작업을 빠르게 번갈아 실행함으로써, 사용자는 여러 프로그램이 동시에 실행되는 것처럼 느끼게 된다.

### 주요 동작 과정

1. **인터럽트/시스템 콜 발생**: 타이머 인터럽트(시간 할당량 만료)나 입출력 요청이 발생한다.
2. **현재 상태 저장**: 실행 중이던 프로세스의 작업 정보를 PCB에 저장한다.
3. **다름 프로세스 선택**: OS 스케줄러가 다음에 실행할 프로세스를 선택한다.
4. **상태 복원**: 선택된 프로세스의 PCB에서 이전 상태를 읽어와 CPU 레지스터에 로드한다.
5. **실행 재개**: 복원된 PC(Program Counter) 지점부터 프로세스를 다시 실행한다.

### 프로세스와 스레드 컨텍스트 스위칭 차이

| **구분** | **프로세스 컨텍스트 스위칭** | **스레드 컨텍스트 스위칭** |
| --- | --- | --- |
| **공유 메모리** | 없음 (독립된 주소 공간) | 있음 (Code, Data, Heap 공유) |
| **오버헤드** | **큼** | **작음** |
| **TLB 캐시** | 캐시 플러시(Flush) 필요 | 캐시 유지 가능 |

### 오버헤드 문제

컨텍스트 스위칭 중에는 CPU가 실제 작업을 하지 않고 OS 코드를 실행한다.

- 시간 손실: 레지스터 저장/복원 및 스케줄러 실행에 시간이 들어간다.
- 캐시 미스: CPU 캐시 메모리 및 TLB가 무효화되어 성능이 저하될 수 있다.

> 컨텍스트 스위칭 주기가 너무 짧으면 오버헤드가 커져 전체 시스템 성능이 떨어지고, 너무 길면 반응성이 떨어지므로 적절한 타임 슬라이스 설정이 중요하다.

## 연결

- 전환 빈도는 CPU 스케줄링의 타임 퀀텀이 결정한다. 퀀텀이 짧으면 응답성은 좋아지지만 오버헤드가 커진다.
- 요청마다 실행 흐름을 새로 만들지 않고 미리 만들어 돌려쓰는 이유가 이 비용이며, 커넥션 풀이 같은 발상이다.
