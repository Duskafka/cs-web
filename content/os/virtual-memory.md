# 가상 메모리

각 프로세스에게 "이 메모리는 전부 네 것"이라는 환상을 준다. MMU 가 페이지 테이블을 참조해 가상 주소를 물리 주소로 변환하고, 자주 쓰는 변환은 TLB 에 캐시한다.

## 페이지 폴트

접근한 페이지가 물리 메모리에 없으면 페이지 폴트가 나고 커널이 디스크에서 읽어온다. 이때 어떤 페이지를 내보낼지 고르는 교체 알고리즘(LRU, Clock)은 캐싱 전략의 축출 정책과 사실상 같은 문제다.

요구 페이징이 과해져 페이지 폴트 처리에만 시간을 쓰는 상태를 **스래싱(thrashing)** 이라 한다.

## 연결

- 프로세스 전환 시 페이지 테이블이 바뀌므로 컨텍스트 스위칭 비용이 커진다.
- 데이터베이스는 OS 페이지 캐시를 우회하고 직접 버퍼 풀을 관리하는데, 이유는 인덱스 접근 패턴을 자기가 더 잘 알기 때문이다.
