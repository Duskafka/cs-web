CPU 스케줄링은 OS의 스케줄러가 CPU를 어떤 프로세스에 할당할지 결정하는 작업이다. CPU 이용률을 극대화하고 응답 시간을 줄여 멀티태스킹 환경의 효율성을 높이는 것이 핵심 목적이다.

### 선점과 비선점

스케줄링 알고리즘은 CPU 주도권을 강제로 빼앗을 수 있는지에 따라 둘로 나뉜다.

| **구분** | **선점형 (Preemptive)** | **비선점형 (Non-Preemptive)** |
| --- | --- | --- |
| **특징** | OS가 실행 중인 프로세스의 CPU를 **강제로 회수** 가능 | 프로세스가 스스로 종료되거나 I/O를 기다릴 때까지 **Wait** |
| **장점** | 높은 응답성 (현대 OS가 채택) | 컨텍스트 스위칭 오버헤드가 적음 |
| **단점** | 컨텍스트 스위칭 오버헤드 발생 | 긴 작업이 CPU를 독점할 위험 (기아 현상) |

### 주요 스케줄링 알고리즘

- **비선점형 알고리즘**
    - **FCFS(First-Come, First-Served)**: 먼저 도착한 순서대로 처리한다. 앞에 긴 작업이 있으면 뒤쪽 작업이 계속 기다리는 호위 효과(Convey Effect)가 발생할 수 있다.
    - **SJF(Shortest Job First)**: 실행 시간이 가장 짧은 프로세스를 먼저 처리한다. 대기 시간을 최소화하지만, 긴 작업은 기아 현상(Starvation)이 발생할 수 있다.
- **선점형 알고리즘**
    - **Roung Robin(RR):** 동일한 시간 할당량(Time Slice)을 부여받고 순서대로 CPU를 사용한다. 할당량이 너무 크면 FCFS와 같아지고, 너무 작으면 컨텍스트 스위칭 오버헤드가 커진다.
    - **SRTF(Shortest Remaining Time First)**: SJF의 선점형 버전으로 남아있는 실행 시간이 가장 짧은 프로세스가 들어오면 현재 프로세스를 중단하고 CPU를 넘긴다.
    - **다단계 큐(Multilevel Queue)**: 프로세스를 성격(예: 백그라운드 작업, 포그라운드 작업)에 따라 여러 큐로 나누고 각 큐마다 다른 스케줄링 알고리즘을 적용한다.
    - **다단계 피드백 큐(Multilevel Feedback Queue)**: 프로세스가 큐 사이를 이동할 수 있게 만든 방식이다. CPU를 오래 사용하는 프로세스는 우선순위가 낮은 큐로 내려가며 현대 대부분의 OS가 변형하여 사용한다.

### 주요 평가 지표

- **CPU 이용률(Utilization)**: 단위 시간당 완료된 프로세스 수
- **처리량(Throughput)**: 단위 시간 당 완료된 프로세스 수
- **반환 시간(Turnaround Time)**: 프로세스가 요청되어 종료될 때까지 걸린 전체 시간
- **대기 시간(Waiting Time)**: 프로세스가 준비 큐에서 기다린 시간의 합
- **응답 시간(Response Time)**: 프로세스 요청 후 첫 번째 반응이 나올 때까지 걸린 시간

## 연결

- 스케줄링 단위는 대부분의 현대 OS 에서 프로세스가 아니라 스레드다.
- 요청을 서버에 배분하는 로드 밸런싱도 라운드 로빈, 최소 연결 같은 같은 아이디어를 쓴다.
- 부팅 직후 스케줄러가 어떻게 초기화되는지는 운영체제 부팅 과정에서 다룬다.
