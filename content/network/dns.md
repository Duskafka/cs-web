# DNS

`example.com` 같은 이름을 `93.184.216.34` 같은 주소로 바꾼다. 전 세계가 쓰는 가장 큰 분산 시스템 중 하나다.

## 해석 순서

1. 브라우저 캐시 → OS 캐시 → hosts 파일
2. 재귀 리졸버(보통 ISP 나 8.8.8.8)
3. 루트 → TLD(`.com`) → 권한 네임서버

각 단계가 TTL 만큼 결과를 캐시한다. 이 계층적 캐시 구조는 캐싱 전략의 교과서적 사례다.

## 설계가 주는 교훈

DNS 는 강한 일관성을 포기하고 가용성과 분할 내성을 택했다. 레코드를 바꿔도 TTL 이 만료될 때까지 옛 값이 돌아다닌다. 이 절충이 바로 CAP 정리가 말하는 선택이다.

## 연결

- 해석이 끝나야 TCP/IP 연결을 시작할 수 있다.
- DNS 라운드 로빈은 가장 단순한 로드 밸런싱 기법이다.
