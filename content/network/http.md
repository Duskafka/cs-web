# HTTP

클라이언트가 요청하고 서버가 응답하는 **무상태** 프로토콜이다. 상태가 없기 때문에 서버를 수평 확장하기 쉽고, 그 성질을 [[로드 밸런싱]]이 그대로 활용한다.

## 버전별 병목 해소

- **HTTP/1.1**: 연결 재사용(keep-alive)은 되지만 응답이 순서대로 나가야 해서 **HOL 블로킹**이 있다.
- **HTTP/2**: 하나의 TCP 연결에서 스트림을 다중화하고 헤더를 압축한다. 다만 [[TCP/IP]] 레벨의 패킷 손실에는 여전히 취약하다.
- **HTTP/3**: QUIC(UDP) 위로 옮겨 전송 계층 HOL 블로킹까지 없앴다.

## 주요 상태 코드

- `2xx` 성공, `3xx` 리다이렉트, `4xx` 클라이언트 오류, `5xx` 서버 오류
- `304 Not Modified` 는 [[브라우저 캐시]] 재검증의 핵심이다.

## 연결

- 암호화된 형태가 [[HTTPS와 TLS]]다.
- 응답 헤더의 `Cache-Control` 은 [[캐싱 전략]]을 네트워크 계층에서 구현한 것이다.
