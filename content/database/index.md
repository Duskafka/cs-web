# 인덱스

책의 색인과 같다. 테이블 전체를 훑는 대신 정렬된 구조를 타고 내려가 원하는 행의 위치를 찾는다.

## 왜 B+Tree 인가

메모리 자료구조라면 해시 테이블이 더 빠를 수도 있다. 하지만 디스크는 블록 단위로 읽으므로 **트리의 높이 = 디스크 접근 횟수**가 된다. B+Tree 는 한 노드에 수백 개의 키를 담아 높이를 3~4 로 유지하고, 리프를 연결 리스트로 이어 범위 질의까지 빠르게 처리한다. 구조적으로는 이진 트리를 디스크에 맞게 넓힌 것이다.

## 공짜가 아니다

- 쓰기마다 인덱스도 갱신해야 하므로 INSERT/UPDATE 가 느려진다.
- 복합 인덱스 `(a, b)` 는 `a` 단독 조회에는 쓰이지만 `b` 단독 조회에는 안 쓰인다(왼쪽 접두사 규칙).
- 카디널리티가 낮은 컬럼(성별 등)의 인덱스는 대개 쓸모가 없다.

## 연결

- 인덱스 생성은 결국 대량 정렬 알고리즘이다.
- 인덱스 페이지는 버퍼 풀에 캐시되며, 그 교체 정책은 가상 메모리의 페이지 교체와 같은 문제다.
